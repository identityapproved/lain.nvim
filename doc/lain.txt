*lain.nvim* *lain* *colorscheme-lain*

==============================================================================
INTRODUCTION                                                    *lain-intro*
==============================================================================

lain.nvim is a dark colorscheme in the lain palette: black ground, rose
chrome, ochre text. Rose carries the interface - statusline, titles,
keywords. Ochre carries content - body text, selection, search. Comments
are a neutral grey, the one unmistakable "this is not code" signal.
Unofficial fan project. Not affiliated with, endorsed by, or connected to
the rights holders of Serial Experiments Lain. The code is MIT; no artwork,
frames, or logos are included or redistributed.

==============================================================================
REQUIREMENTS                                                     *lain-req*
==============================================================================

- Neovim 0.11 or newer.
- A truecolor terminal. The lain ramps need 24-bit color, and there is no
  256-color fallback by design: at 256 colors the rose and ochre steps
  quantise onto the same xterm pink band and stop being distinguishable.

Both are checked at runtime: see |lain-health|.

==============================================================================
INSTALL                                                      *lain-install*
==============================================================================

With lazy.nvim:
>lua
    {
      "identityapproved/lain.nvim",
      lazy = false,
      priority = 1000,
      config = function()
        vim.cmd.colorscheme("lain")
      end,
    }
<
Under LazyVim:
>lua
    {
      "identityapproved/lain.nvim",
      priority = 1000,
    },
    {
      "LazyVim/LazyVim",
      opts = {
        colorscheme = "lain",
      },
    },
<
==============================================================================
OPTIONS                                                       *lain-options*
==============================================================================

Options are passed through the setup table:
>lua
    require("lain").setup({
      styles = { visual = "fill" },
      terminal_colors = true,
      transparent = false,
      on_highlights = nil,
    })
<
styles.visual (string, default "fill")        *lain-option-styles.visual*
    The selection style. "fill": an ochre fill with black text. "tint": a
    dark tint, syntax colors intact.

terminal_colors (boolean, default true)       *lain-option-terminal_colors*
    Sets g:terminal_color_0 through g:terminal_color_15 on load.

transparent (boolean, default false)              *lain-option-transparent*
    Drops the background from the groups that paint the window ground -
    Normal, and the plugin windows that restate it - so the terminal shows
    through. Floats, popups and the statusline keep their surface ground:
    they have to stay readable over whatever is behind the terminal.
    FloatShadow keeps its black, since a shadow on the wallpaper is the
    point of a shadow.

    lain's ground is pure black, so this changes nothing against a black
    terminal. It is for a translucent or image background.

on_highlights (function, default nil)          *lain-option-on_highlights*
    A hook run over the finished group table, so you can patch lain
    without forking it. See |lain-on-highlights|.

==============================================================================
OVERRIDES                                                *lain-on-highlights*
==============================================================================

The palette is the theme and is not configurable. Individual groups are:
on_highlights is handed the assembled table and the semantic palette, and
mutates the table in place.
>lua
    require("lain").setup({
      on_highlights = function(groups, palette)
        groups.Comment = { fg = palette.syn.comment, italic = true }
        groups["@keyword.return"] = { fg = palette.ui.accent, bold = true }
        groups.MyPluginTitle = { fg = palette.ui.fg_chrome }
      end,
    })
<
The palette argument is the table documented under |lain-palette|: ui,
syn, diag and diff. Use it rather than raw hex and an override tracks the
ramp instead of drifting from it.

The hook runs last, after the styles.visual variant and after transparent
have been applied, so it can override those too - setting a bg on Normal
puts the ground back under transparent. Groups it does not name are left
alone, and names lain does not define are created.

It runs on every load, over a table rebuilt each time, so removing the
hook and reloading restores stock lain.

Two failures are survivable and are reported rather than raised, because
a mistake in a config is not a reason to hand back an unstyled editor:

    the hook errors      what it wrote before the error still applies,
                         and the rest of the groups load normally
    a spec nvim rejects  that one group is skipped and named in the
                         message; every other group still loads

Both print through ErrorMsg and land in |:messages|. |:checkhealth| lain
reports whether a hook is set, since it means the groups on screen are no
longer stock lain.

==============================================================================
TERMINAL                                                     *lain-terminal*
==============================================================================

With terminal_colors enabled the sixteen ANSI slots are the palette's
terminal mapping, matching the lain kitty theme, so :terminal inside
Neovim and a kitty tab agree. Green renders as ochre and blue as grey;
programs that hardcode "green means success" read as ochre against rose
for failure - the hue still separates, only the names lie.

==============================================================================
LUALINE                                                       *lain-lualine*
==============================================================================

A lualine theme ships at lua/lualine/themes/lain.lua. It loads as the
auto theme once the colorscheme is active, since vim.g.colors_name is
"lain", or explicitly with require("lualine").setup({ theme = "lain" }).
The bar is rose chrome text on the surface ground, ochre and rose and
cream mode fills carrying black text, dim ochre for inactive sections.
Every fg/bg pair clears WCAG 4.5:1.

==============================================================================
PLUGINS                                                       *lain-plugins*
==============================================================================

Beyond the core and treesitter groups, lain styles these plugins:

    blink.cmp, bufferline.nvim, crates.nvim, dashboard-nvim, flash.nvim,
    fzf-lua, grug-far.nvim, lazy.nvim, marks.nvim, mason.nvim, mini.icons,
    noice.nvim, nvim-dap, nvim-dap-ui, nvim-dap-virtual-text,
    outline.nvim, snacks.nvim, todo-comments.nvim, trouble.nvim,
    which-key.nvim

Plugins that only link to core groups need nothing here; they follow
Normal, Pmenu, FloatBorder and the diagnostic groups on their own. The
list above covers the ones that name their own groups, or that ship
hardcoded colors a colorscheme has to displace - crates.nvim's popup
pills, for one. outline.nvim is a further case: it installs its defaults
once at setup and never rebuilds them, so after a later :colorscheme its
groups would be gone if lain did not define them.

==============================================================================
PALETTE                                                       *lain-palette*
==============================================================================

Colors resolve through semantic tokens in lua/lain/palette.lua, never a
raw hex. Every token binds to a step of the ramps in lua/lain/ramp.lua.
    ui      ground and chrome: bg, bg_surface, bg_hover, bg_fill,
            fg_on_fill, fg, fg_chrome, fg_dim, fg_muted, rule, decoration,
            border, border_focus, accent, alert, alert_fg
    syn     syntax: text, type, string, punct, comment, keyword, preproc,
            fun, special
    diag    diagnostics: error, warn, info, hint, ok, warn_fill, ok_fill
    diff    diff: add, change, delete, text

The ramps: back_1 through back_12, fore_1 through fore_12, high_1 through
high_12, plus the accents accent, success_fg, success_bg, warning_bg,
error_bg, error_fg and white_pure.

==============================================================================
HEALTH                                                        *lain-health*
==============================================================================

>vim
    :checkhealth lain
<
reports on the two hard requirements and on what the theme resolved to:

    Neovim version    an error below 0.11, the floor lain.load() enforces
    Truecolor         an error if termguicolors is off, a warning if
                      nothing advertises 24-bit color
    Colorscheme       whether lain is active and the background is dark
    Configuration     the resolved options, and whether all sixteen
                      terminal_color_* slots are set

Truecolor is read from COLORTERM, from a TERM naming a direct-color
entry, and - inside tmux - from what tmux negotiated with its client.
That last one matters: tmux does not forward COLORTERM, so a session with
working truecolor otherwise reports as having none. If tmux is not set up
for it, the advice is the tmux.conf line rather than a COLORTERM export:
>
    set -as terminal-features ",*:RGB"
<
The result is a warning, not an error: plenty of 24-bit terminals
advertise nothing. It is worth saying either way, since there is no
256-color fallback to degrade into.

==============================================================================
TESTS                                                         *lain-tests*
==============================================================================

>sh
    tests/run.sh
<
runs the suite: lint, palette conformance (no raw hex outside
lua/lain/ramp.lua, every token bound to a ramp step), WCAG contrast over
every rendered pair, the option variants, a headless smoke load that also
asserts no group renders a colour outside the ramp, the on_highlights
contract including what a broken hook costs, a headless :checkhealth that
must come back clean, and a snapshot of the lain-defined groups.

That smoke assertion is a coverage check rather than a palette one. A
group lain never names keeps nvim's default colour, which is how OkMsg
put a mint green into a theme with no green. Only the vimscript
expression-parser groups and the 'redrawdebug' overlay are exempt: both
are debug markers with hardcoded colours, unreachable in ordinary use.

The variant check is what keeps transparent honest. The list of
ground-painting groups in lua/lain/groups/init.lua is written by hand, so
the test asserts that every group painting the window ground is either on
it or an explicit shadow exemption, and that transparent touches nothing
else. A plugin group added later that paints the ground and is not listed
fails the suite by name rather than quietly staying opaque.

The lint step skips a tool it cannot find, which suits a dev box but
would let CI pass having checked nothing. CI therefore runs it as
LINT_STRICT=1 tests/lint.sh, where a missing or unrunnable tool fails.
luacheck flags live in .luacheckrc, so a bare luacheck from the repo
root agrees with the suite.

luacheck ships a #!/usr/bin/env lua shebang but is built against one Lua
slot, so on a box whose lua is a different version it sits on PATH and
cannot load its own modules. The lint step tries the versioned
interpreters against it before giving up, and says which one it used.
